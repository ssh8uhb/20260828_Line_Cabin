## 1. 时间线

### 阶段一（2026-08-28）：立项与技术选型

用户需求（原文要点）：

1. 先分析开源项目 https://github.com/Animnia/pure-line-room（网页端线条三维小屋），要做一个类似的项目。
2. 总体场景：识别小屋 DWG 图纸 → 导出描述墙体/门窗/楼梯/层高等信息的 JSON → 按 JSON 建白模 →
   白模截图 + 提示词（外立面材质、风格）→ 扩散模型渲染效果图；小场景 = 其中的"按 JSON 建白模"。
3. 追问：白模用什么建？是否必须装 Blender？"我需要把总体场景做成产品，不能要求用户的电脑上都装有 Blender"。
4. 追问：Three.js 能否集成到 .exe 桌面端？

结论：

- 路线可行。DWG → JSON 由用户侧 CAD 插件完成（插件可按图导出，JSON 具备可解释性），
  本项目专注 JSON → 白模这一段。
- **白模用 Three.js 在浏览器端参数化建模**，不用 Blender：Three.js 可直接跑在 Electron 里打包成 .exe，
  用户无需安装任何建模软件；Blender 只适合做一次性离线处理，不适合做产品依赖。
- pure-line-room 的参考价值：**仅限展示层**（线条风格、交互、离线单页结构），
  它的几何是手写/硬编码的房间，不能作为参数化建模的依据。

## 2. 关键决策汇总

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 建模方案 | Three.js 参数化建模（不用 Blender） | 产品不能要求用户装建模软件；Three.js 可打包进 Electron |
| 交付形态 | 单页应用、无构建工具、可 file:// 离线打开 | 便于后续打包 .exe，也便于无头出图 |
| JSON 来源 | CAD 插件导出，字段可解释 | 不需要做 DWG 解析，本项目专注白模 |
| 线稿 | 素模默认 + 线稿可切（30° 二面角阈值，黑线） | 线稿是可选条件图，不是唯一正确形态 |
| 门窗 | 2D CAD 大样 → 参数化族 | 可按洞口尺寸/开向自动摆放缩放 |
| 挑檐 | 截面 DXF → 沿路径放样 | 与设计端放样逻辑一致 |
| 地面 | OBJ 三角网 + 双控制点配准 | 明确"地面与建筑的定位关系"且实现简单 |
| Git 推送 | HTTPS + Windows 凭据管理器 | 本机无 SSH 密钥 |
| 仓库约定 | 每个新项目登记一次 safe.directory | 用户明确选择的安全方案 |

## 5. 附录：如何重新导出会话原文

原始 JSONL 每行是一条事件；对话正文在 `type == "response_item"` 且 `payload.type == "message"` 的行里。
只提取用户与助手消息的参考做法（Node 脚本，在本机运行）：

```js
const fs = require("fs");
const p = "C:/Users/lenovo/.codex/sessions/2026/08/28/rollout-2026-08-28T14-36-18-01a04715-5f4e-75c3-8b82-2897b4b8a913.jsonl";
for (const ln of fs.readFileSync(p, "utf8").split("\n").filter(Boolean)) {
  let o; try { o = JSON.parse(ln); } catch { continue; }
  if (o.type !== "response_item") continue;
  const pl = o.payload || {};
  if (pl.type !== "message" || !["user", "assistant"].includes(pl.role)) continue;
  const text = (pl.content || []).map(c => c.text || c.input_text || "").join("\n");
  if (text.trim()) console.log(`[${o.timestamp}] ${pl.role}: ${text}`);
}
```

注意：原始记录里包含工具原始输出、临时路径与截图数据，导出后请自行过滤；
本纪要已确认其中不含任何密钥或凭据。
